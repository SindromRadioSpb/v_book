# Настройки извлечения термов — справочник

> Описывает все параметры вкладки **Terms**, что они означают и как влияют на результат.
> Написан для обычного пользователя — без программистского жаргона.

---

## Если вы открыли вкладку Terms впервые

Пять вещей, которые нужно знать сразу:

1. **Кнопка «Extract Terms»** запускает анализ текстов. Без неё список будет пустым.
2. **«Min freq»** — это фильтр отображения. Он ничего не удаляет.
3. **«Store hapax»** влияет на то, что будет сохранено в базу при извлечении.
4. **Bigrams / Trigrams** определяют, словосочетания какой длины искать.
5. **Режим «Full Overwrite»** удаляет старые термы и извлекает заново. **«Merge»** — добавляет к существующим.

---

## Что такое «терм» в этой программе

Программа ищет **тематически важные языковые единицы** — слова и словосочетания, которые характеризуют именно вашу тему.

Термы бывают двух типов:

| Тип | Как находится | Пример |
|-----|--------------|--------|
| **N-грамма** | Статистически: ищет последовательности слов, которые часто стоят вместе | «международное право», «базовый уровень» |
| **NP-чанк** | Грамматически: NLP-анализатор выделяет именные группы (существительное + зависимые слова) | «международная правовая система», «базовый уровень подготовки» |

Один и тот же фрагмент может быть одновременно n-граммой и NP-чанком — тогда в колонке **Kind** появится `ngram,np`.

## Параметры извлечения — что каждый делает

### Include NP chunks (галочка)

**Что делает:** включает или отключает поиск NP-чанков (именных групп).

| Состояние | Результат |
|-----------|-----------|
| ✅ Включено (по умолчанию) | Программа ищет и n-граммы, и NP-чанки |
| ☐ Отключено | Только n-граммы; именные группы не анализируются |

**Когда отключить:**
- Если важны только статистические сочетания слов.
- Если анализ NP замедляет работу на очень большом корпусе.
- Если NLP-модель для вашего языка не установлена.

---

### N-grams: Bigrams / Trigrams (галочки)

**Что делает:** задаёт, сочетания какой длины искать.

| Настройка | Что ищется |
|-----------|-----------|
| ✅ Bigrams | Сочетания из **2 слов** подряд: «система управления», «базовый курс» |
| ✅ Trigrams | Сочетания из **3 слов** подряд: «система управления данными», «базовый курс английского» |
| Оба включены | И двухсловные, и трёхсловные сочетания |
| Оба отключены | N-граммы не ищутся вообще (только NP, если включено) |

**Совет:**
- Для начала работы с темой — включите оба.
- Для поиска только коротких устойчивых сочетаний — только Bigrams.
- Trigrams дают больше данных, но список будет длиннее.

---

### Max NP length (счётчик, диапазон 2–5)

**Что делает:** ограничивает максимальную длину NP-чанка (в словах).

| Значение | Что включается |
|---------|----------------|
| 2 | Только 2-словные именные группы |
| 3 | До 3 слов |
| 5 (по умолчанию) | До 5 слов — самый полный режим |

**Пример:**
- При Max NP = 3: «системы управления» ✅, «система управления базами данных» ❌ (4 слова)
- При Max NP = 5: оба найдены ✅

**Когда уменьшить:**
- Если список очень длинный и засорён длинными нечёткими фразами.
- На очень больших корпусах, где длинные NP редко повторяются.

---

### Min freq (счётчик, от 1 до 100)

**Что делает:** задаёт минимальную частоту для **отображения** терма в таблице.

⚠️ **Важно: это фильтр отображения, не фильтр хранения.**
Термы с частотой ниже порога хранятся в базе, но не показываются в списке.

| Значение | Что видно |
|---------|-----------|
| 1 | Все термы, включая однократные |
| 2 | Только термы, встретившиеся 2+ раза |
| 5 | Только термы с 5+ вхождениями |
| 10 | Только высокочастотные термы |

**Быстрые пресеты:**
- **All (1)** — показать всё, включая редкие
- **Common (3)** — скрыть очень редкие
- **Strict (5)** — только надёжные термы
- **High (10)** — только очень частые

**Совет:** начните с «All (1)», изучите данные, затем поднимите порог, чтобы убрать шум. Данные при этом не потеряются — понизьте порог обратно в любой момент.

---

### Min doc freq (счётчик, от 1 до 50)

**Что делает:** задаёт минимальное количество **документов**, в которых должен встретиться терм, чтобы попасть в список.

Это **не то же самое**, что Min freq!

| Параметр | Что считает |
|----------|------------|
| **Min freq** | Количество **вхождений** в текст (во всех документах вместе) |
| **Min doc freq** | Количество **документов**, в которых хотя бы один раз встретился терм |

**Пример:**
- Терм «аварийный клапан» встретился 50 раз — но только в одном документе.
- При Min doc freq = 1: терм показан.
- При Min doc freq = 2: терм скрыт, потому что он есть только в 1 документе из всех.

**Когда повысить Min doc freq:**
- Когда в корпусе есть один очень длинный документ, который «засоряет» список своими специфическими фразами.
- Чтобы оставить только термы, которые повторяются хотя бы в нескольких источниках.

---

### Mode (режим извлечения)

Это важнейший параметр. Он определяет, что произойдёт со старыми данными при новом извлечении.

#### Full Overwrite (Полная перезапись)

- **Что делает:** удаляет **все** существующие термы проекта и извлекает заново с нуля.
- **Когда использовать:** первый запуск, или когда нужно полностью обновить данные.
- **Важно:** записи переводов (TM-записи) **не удаляются** — они сохраняются.
- **Программа покажет предупреждение**, если у удаляемых термов есть переводы.

#### Merge (Добавить)

- **Что делает:** добавляет новые термы к уже существующим, ничего не удаляя.
- **Когда использовать:** добавляете в проект новые документы и хотите дополнить список термов.
- **Важно:** старые термы остаются в базе, новые добавляются рядом.

#### Replace Layer (Заменить слой)

- **Что делает:** удаляет только термы определённого размера n-граммы (например, только биграммы), затем извлекает их заново. Термы других размеров не трогает.
- **Когда использовать:** хотите перезаписать только биграммы, сохранив NP-чанки.
- **Пример:** у вас есть биграммы и NP-чанки. Вы хотите переизвлечь только биграммы с новыми настройками. Выберите «Replace Layer» + поставьте только Bigrams.

**Сравнительная таблица режимов:**

| Режим | Удаляет старые термы | Добавляет новые | Переводы сохраняются |
|-------|---------------------|-----------------|----------------------|
| Full Overwrite | Все ✅ | Да | Да ✅ |
| Merge | Нет | Да | Да ✅ |
| Replace Layer | Только выбранный слой | Да | Да ✅ |

---

### Store hapax (галочка)

**Hapax legomenon** — это слово или фраза, встретившаяся в корпусе **ровно один раз**.

**Что делает:**
- ✅ Включено (по умолчанию): при извлечении все однократные термы **сохраняются** в базу. Потом их можно показать или скрыть через Min freq.
- ☐ Отключено: при извлечении однократные термы **не сохраняются** вообще. Их нельзя будет показать, не переизвлекая.

**Когда отключить:**
- На очень большом корпусе (тысячи документов), где однократные термы занимают огромное место в базе.
- Если уверены, что однократные вхождения для вас не интересны.

**Правило:** если сомневаетесь — оставьте включённым. Хранить лишнее дешевле, чем переизвлекать.

## Метрики в таблице Terms — что они означают

Программа рассчитывает несколько числовых оценок для каждого терма. Они помогают понять, насколько «важен» терм.

### Freq (частота)

Сколько раз этот терм встретился во всех текстах проекта. Простой подсчёт.

### DocFreq (документальная частота)

В скольких документах этот терм встретился хотя бы один раз.
Отличается от Freq: если документ длинный, одно слово может встретиться 100 раз — но DocFreq считает это как «1 документ».

### Members (количество вариантов)

Кластер объединяет похожие формы одного выражения. Members показывает, сколько разных текстовых форм попало в этот кластер.

### PMI (Pointwise Mutual Information — взаимная информация)

**Простыми словами:** насколько слова в этом сочетании «любят» стоять вместе, а не порознь.

- Высокий PMI → слова в этом сочетании встречаются вместе значительно чаще, чем по отдельности.
- Низкий или отрицательный → слова встречаются вместе случайно.
- Доступен только для биграмм (2 слова).

### LLR (Log-Likelihood Ratio — логарифм правдоподобия)

**Простыми словами:** статистическая надёжность того, что сочетание устойчивое, а не случайное.

- Чем выше LLR, тем «надёжнее» сочетание.
- LLR учитывает размер корпуса — это надёжнее PMI для больших и малых текстов.

### Dice (коэффициент Дайса)

**Простыми словами:** сбалансированная мера: насколько часто слова встречаются вместе относительно того, как часто они встречаются порознь.

- Значение от 0 до 1.
- 1.0 = слова всегда встречаются вместе.
- 0.0 = слова никогда не встречаются вместе.

### Weirdness (нестандартность)

**Простыми словами:** насколько этот терм специфичен для вашего текста по сравнению с обычным языком.

- Weirdness > 1 → терм встречается в вашем тексте чаще, чем в обычной речи → тематически специфичный.
- Weirdness < 1 → терм более характерен для общего языка, чем для вашей темы.

Для расчёта нужен **референсный корпус** (обычная речь для сравнения).

### Keyness (ключевость)

**Простыми словами:** насколько этот терм отличает вашу тему от всего остального.

Рассчитывается методом LLR: сравнивает частоту терма в вашем тексте с частотой в референсном корпусе.

- Высокий Keyness → терм редок в обычном языке, но характерен для вашей темы.

### Termhood (терминологичность)

**Простыми словами:** общая оценка «насколько это настоящий термин».

Формула учитывает сразу: Keyness, Weirdness и Freq. Это составная оценка.

**Какую метрику использовать для сортировки:**

| Цель | Лучшая метрика |
|------|---------------|
| Найти самые характерные для темы слова | Keyness или Termhood |
| Найти слова, специфичные для текста (редкие в языке) | Weirdness |
| Найти устойчивые словосочетания | PMI или LLR |
| Найти общий рейтинг «важности» | Termhood |
| Просто посмотреть, что часто встречается | Freq |

## Фильтры в таблице Terms

### Source (источник) — выпадающий список

| Значение | Что показывает |
|---------|----------------|
| All | Все термы |
| N-grams | Только статистические n-граммы |
| NP | Только NP-чанки (именные группы) |

### Filters (кнопка) — TermsFilterDialog

Открывает расширенный фильтр. Позволяет выбрать:
- **Kind**: ngram, np, ngram,np (по отдельности или в любой комбинации)
- **Noise**: статус шума — auto, manual, valid_auto, valid_manual, unclassified

### Preset (пресет сортировки)

| Пресет | Что делает |
|--------|-----------|
| freq | Сортировка по частоте (самые частые первые) |
| strong | По силе ассоциации (PMI / LLR) |
| balanced | Компромисс между частотой и силой |
| termhood | По составной оценке терминологичности |
| keyness | По ключевости для темы |
| weirdness | По нестандартности (специфичности для текста) |

## Рекомендуемые настройки для разных задач

### Первое знакомство с текстами

```
Bigrams: ✅
Trigrams: ✅
Include NP: ✅
Max NP length: 5
Store hapax: ✅
Min freq: 1  (или «All»)
Min doc freq: 1
Mode: Full Overwrite
```

Цель: увидеть максимум данных, понять, что есть в текстах.

---

### Работа с большим корпусом (500+ документов)

```
Bigrams: ✅
Trigrams: ✅
Include NP: ✅
Max NP length: 3  (сократить для скорости)
Store hapax: ☐  (не хранить редкие)
Min freq: 3  (или «Common»)
Min doc freq: 2  (хотя бы 2 документа)
Mode: Full Overwrite
```

Цель: получить надёжные термы без перегрузки базы данных.

---

### Добавить новые документы к существующему проекту

```
Min freq: (ваши текущие настройки)
Mode: Merge
```

Цель: дополнить список, не потеряв уже накопленное.

---

### Перезаписать только биграммы, сохранить NP-чанки

```
Bigrams: ✅
Trigrams: ☐
Mode: Replace Layer
```

Цель: обновить двухсловные n-граммы с новыми параметрами.

## Частые вопросы

### Почему список пустой после открытия вкладки?

Нужно нажать **«Extract Terms»**. Без извлечения список не заполняется.

### Я поднял Min freq — термы исчезли. Они удалены?

Нет. Min freq — это фильтр отображения. Опустите Min freq обратно — все термы снова появятся.

### Почему одинаковые слова видны в Dictionary и в Terms?

Это разные сущности:
- В **Dictionary** — отдельные слова (леммы).
- В **Terms** — словосочетания (кластеры). Слово может быть частью кластера.

### Что делает кнопка «Recalculate»?

Пересчитывает метрики (Keyness, Weirdness) по новым данным референсного корпуса, **не переизвлекая** термы. Быстрее, чем Full Overwrite.

### Почему у некоторых термов нет метрик PMI / LLR / Dice?

Эти метрики рассчитываются только для **биграмм** (2 слова). Для NP-чанков и триграмм они не применимы — в этих ячейках будет пусто.

### Откуда берётся колонка Weirdness / Keyness?

Эти метрики требуют **референсного корпуса** — набора текстов «обычного» языка для сравнения. Если референсный корпус не подключён или не совпадает с текущим, метрики могут быть устаревшими. В таком случае появляется предупреждение о staleness (устаревших данных).
