# Справочник по сущностям и логике программы
### Как понимать то, что вы видите на экране

> **Для кого этот документ:** для любого пользователя, открывшего программу впервые.
> Написан человеческим языком — без программистского жаргона.
> Уровень 1 → уровень 2 → уровень 3: от простого к сложному.

---

## Если вы открыли программу впервые — прочитайте сначала это

Десять вещей, которые нужно знать с самого начала:

1. **Лемма** — это слово в основной словарной форме.
2. **Терм** — это важная единица по теме текста: слово или словосочетание.
3. **Не всё, что состоит из 3 слов — триграмма.** Может быть NP-чанк.
4. **NP-чанк** — это смысловое словосочетание, а не просто слова подряд.
5. **Фильтр ничего не удаляет.** Он только скрывает или показывает.
6. **Noise — не значит ошибка программы.** Это значит: запись признана малополезной.
7. **"manual"** означает: решение принял пользователь.
8. **"auto"** означает: решение приняла программа.
9. **В разных вкладках показываются разные сущности** — не дублирование.
10. **Если что-то исчезло — сначала проверь фильтры.**

## 1. Что делает программа

Программа помогает работать с текстами на иностранном языке.

Она:
- читает загруженные тексты;
- выделяет из них языковые единицы — слова, словосочетания, именные группы;
- предлагает переводы и позволяет их проверять;
- помогает пользователю находить важные термины по теме;
- позволяет отмечать полезные и бесполезные записи;
- хранит всё это в базе данных для повторного использования.

Итог работы с программой — **накопленный словарь и база переводов** по изучаемой теме.

---

## 2. Главные сущности программы

В программе есть пять основных типов объектов. Каждый из них виден в своей части интерфейса.

| Сущность | Простыми словами | Где видна | Зачем нужна |
|----------|-----------------|-----------|-------------|
| **Лемма** | Основная форма слова (словарная) | Вкладка Dictionary | Словарь по отдельным словам |
| **Терм** | Важное слово или словосочетание по теме | Вкладка Terms | Тематически значимые единицы |
| **N-грамма** | Последовательность из 2–3 слов подряд | Terms / внутренняя обработка | Устойчивые словосочетания |
| **NP-чанк** | Именная группа, найденная NLP-анализатором | Terms | Смысловые словосочетания |
| **TM-запись** | Строка с переводом | Вкладка Translation Management | Хранить и проверять переводы |

## 3. Чем отличаются лемма, терм, n-грамма и NP-чанк

Это самое важное для понимания программы. Именно здесь чаще всего возникает путаница.

### Лемма

Лемма — это не та форма слова, которая встретилась в тексте, а **нормальная словарная форма**.

Пример:
- В тексте встречается форма глагола — «бежит», «бегут», «бежал».
- Программа приводит все эти формы к основной: **бежать**.
- Именно «бежать» попадает в Dictionary как лемма.

Лемма — это всегда **одно слово** в словарной форме.

### Терм

Терм — это **тематически важная единица**. Она может быть:
- одним словом,
- двумя-тремя словами,
- именной группой.

Программа отбирает термы не просто по частоте, а по тематической значимости для конкретного текста. Терм — это то, что *характеризует* текст, а не просто часто в нём встречается.

### N-грамма

N-грамма — это просто **последовательность слов подряд**, без анализа смысла.

Примеры:
- Биграмма (2 слова): «גוף האדם» (тело человека)
- Триграмма (3 слова): «שיטת טיפול חדשה» (новый метод лечения)

N-грамма выделяется механически: программа смотрит, какие сочетания слов часто встречаются рядом.

### NP-чанк

NP-чанк (именная группа) — это **словосочетание с существительным в центре**, выделенное языковым анализатором по смыслу и грамматике.

Пример:
- «система управления базами данных» — это NP-чанк: центр — существительное «система», вокруг него зависимые слова.

**Ключевое отличие от n-граммы:**
- N-грамма — это любые N слов подряд.
- NP-чанк — это грамматически осмысленная именная группа.

Одно и то же трёхсловное выражение может быть:
- случайной триграммой (если слова стоят рядом случайно),
- осмысленным NP-чанком (если анализатор распознал их как именную группу),
- и тем и другим одновременно.

Смотрите колонку **Kind** во вкладке Terms — там написано, чем именно является каждый терм.

## 4. Как программа создаёт леммы

Простая цепочка шагов:

1. Пользователь загружает текст в проект.
2. Программа разбивает текст на предложения и слова.
3. NLP-анализатор определяет грамматическую форму каждого слова.
4. Программа приводит слово к основной (словарной) форме.
5. Эта форма сохраняется как **лемма** в базе данных.
6. Для каждой леммы считается:
   - **Freq** — сколько раз слово встретилось в текстах,
   - **Docs** — в скольких документах оно встретилось,
   - **Noise** — полезная запись или шумовая,
   - **Entity Class** — является ли это именованной сущностью (имя, город, организация).

Лемма появляется в программе **автоматически** — пользователю не нужно её создавать вручную.

---

## 5. Как программа создаёт термы

1. Программа ищет **n-граммы** — частые сочетания слов подряд в текстах.
2. Если включён режим NP-анализа, она также ищет **NP-чанки** — именные группы.
3. Найденные единицы объединяются в **кластеры** (группы похожих выражений).
4. Каждый кластер ранжируется по **метрикам**: PMI, LLR, Keyness, Termhood и другим.
5. Пользователь видит термы во вкладке **Terms**, может их фильтровать и переводить.

**Почему один терм может быть собран из разных источников:**

| Значение в колонке Kind | Что это значит |
|------------------------|----------------|
| `ngram` | Терм найден только как n-грамма |
| `np` | Терм найден только как NP-чанк |
| `ngram,np` | Терм найден обоими методами одновременно |

Это важно: один и тот же текстовый фрагмент может быть одновременно и биграммой по форме, и NP-чанком по смыслу.

## 7. Что означают статусы — словарь

### Статусы Noise (столбец Noise)

| Что видно в ячейке | Простое объяснение |
|-------------------|-------------------|
| `Noise (auto)` | Программа автоматически решила, что запись шумовая |
| `Noise (manual)` | Пользователь вручную пометил запись как шум |
| `Valid (auto)` | Программа считает запись нормальной и полезной |
| `Valid (manual)` | Пользователь вручную подтвердил, что запись полезна |
| `Noise` *(без суффикса)* | Шумовая — но когда и кем решено, неизвестно (старые данные) |
| `Valid` *(без суффикса)* | Полезная — источник решения неизвестен (старые данные) |
| *(пусто)* | Ещё не классифицировано |

### Статусы перевода (столбец Status)

| Статус | Простое объяснение |
|--------|-------------------|
| `draft` | Черновик — перевод есть, но не проверен |
| `approved` | Одобрен пользователем |
| `rejected` | Отклонён — перевод неверный |
| `deprecated` | Устаревший — был верным, теперь не актуален |

### Статусы Source Ref (столбец Src)

| Значение | Что это означает |
|----------|-----------------|
| `linked` | Источник этой записи активен в проекте |
| `source_missing` | Источник был удалён, но запись сохранена |
| `manual` | Запись создана вручную, без связи с корпусом |

## 8. Чем отличаются автоматические и ручные действия

Программа всегда показывает, **кто** принял решение — человек или алгоритм.

| Суффикс | Кто принял решение | Пример |
|---------|-------------------|--------|
| `(auto)` | Программа, автоматически | `Noise (auto)` — NLP-анализатор пометил как шум |
| `(manual)` | Пользователь, вручную | `Valid (manual)` — вы сами подтвердили полезность |
| *(без суффикса)* | Неизвестно (старые данные) | `Noise` — данные созданы до появления этой системы учёта |

**Почему это важно:**
- Если вы видите `(auto)` — программа решила, но вы можете исправить.
- Если вы видите `(manual)` — кто-то уже проверил вручную.
- Если нет суффикса — это старые данные: проверьте сами, если нужно.

## 9. Что такое фильтры и как ими пользоваться

**Главное правило:** фильтр **ничего не удаляет**. Он только скрывает или показывает записи.

Если запись пропала после изменения фильтра — она никуда не делась. Она просто не отображается при текущих настройках.

### Виды фильтров

**Фильтр по Noise:**
- Позволяет выбрать, какие записи показывать: только noise, только valid, только unclassified, или любую комбинацию.
- Открывается через меню Filters.

**Фильтр по Kind (тип в Terms):**
- Можно показывать только ngram, только np, или оба типа.

**Фильтр по частоте:**
- Позволяет скрыть записи с частотой ниже заданного порога.

**Фильтр по Entity Class:**
- Показывать только имена людей, только организации, только места и т.д.

**Строка поиска:**
- Ищет по тексту записи.
- Фильтр и строка поиска работают одновременно — оба условия применяются сразу.

### Строка состояния

Внизу каждой вкладки показано:

```
Found: 312   |   Noise: 47
```

- **Found:** — сколько записей показано **при текущем фильтре**.
- **Noise:** — сколько шумовых записей **во всём проекте**, независимо от фильтра.

То есть если вы отфильтровали только 20 строк, а `Noise: 47` — это не значит, что 47 из 20 являются шумом. Это означает: в проекте всего 47 шумовых записей.

## 10. Частые ошибки понимания

### Ошибка 1 — «Я не вижу запись — значит, она удалена»

**Не так.** Скорее всего, запись скрыта фильтром.

Что проверить:
- сброс фильтра Noise,
- сброс фильтра Kind,
- очистка строки поиска.

---

### Ошибка 2 — «Если я вижу три слова — это триграмма»

**Не обязательно.** Три слова подряд могут быть:
- триграммой (`ngram`),
- NP-чанком (`np`),
- и тем и другим сразу (`ngram,np`).

Смотрите колонку **Kind** — она скажет точно.

---

### Ошибка 3 — «Noise — это ошибка программы»

**Нет.** Noise — это оценка полезности. Запись «шумовая» означает: по мнению программы (или пользователя), эта единица не несёт тематической ценности. Это не значит, что данные некорректны.

Примеры шумовых записей:
- слово «и», «в», «на» (служебные части речи),
- знаки препинания,
- числа без контекста.

---

### Ошибка 4 — «Valid и Approved — одно и то же»

**Нет.** Это разные оси:

| Понятие | Ось | Что означает |
|---------|-----|-------------|
| `Valid` | Noise-ось | Запись не является шумом |
| `Approved` | Translation-ось | Перевод проверен и одобрен |

Запись может быть `Valid (manual)` (полезная) и при этом иметь статус перевода `draft` (перевод не проверен). Это нормально — это два разных вопроса.

---

### Ошибка 5 — «В Terms и в Dictionary одни и те же данные»

**Нет.** Разные вкладки — разные сущности:

- **Dictionary** → отдельные слова (леммы).
- **Terms** → словосочетания и кластеры (термы).
- **Translation Management** → записи переводов для всех типов.

Одно и то же слово может быть видно в Dictionary как лемма и в Terms как часть терм-кластера — это не дублирование, это разные уровни описания.

---

### Ошибка 6 — «Счётчик Noise в статус-баре показывает мои отфильтрованные строки»

**Нет.** `Noise: N` — это всегда **проектный показатель** (сколько шумовых записей во всём проекте). Фильтры на него не влияют.

## 11. Мини-сценарии: как читать программу

### Сценарий 1 — Я хочу понять, что означает строка во вкладке Terms

1. Посмотри на колонку **Kind**: `ngram`, `np`, или `ngram,np`?
2. Посмотри на **Noise**: полезная запись или шумовая?
3. Посмотри на **Keyness** и **Termhood**: насколько это важная единица для темы?
4. Посмотри на **Translation**: есть ли перевод и в каком он статусе?
5. Если непонятно, почему строка здесь — наведи курсор на ячейку для tooltip.

---

### Сценарий 2 — Я хочу понять, почему запись исчезла

1. Проверь **фильтр Noise** — не скрыты ли записи с определённым статусом.
2. Проверь **фильтр Kind** — не отключён ли нужный тип.
3. Проверь **строку поиска** — не ограничивает ли она результаты.
4. Проверь **фильтр по частоте** — не слишком ли высокий порог.
5. Если всё сброшено и запись всё равно не видна — возможно, она была удалена из проекта (редкий случай).

---

### Сценарий 3 — Я хочу понять, программа это решила или человек

1. Посмотри на **суффикс** в ячейке Noise: `(auto)` или `(manual)`?
2. Наведи курсор — tooltip покажет дату и источник решения.
3. Нет суффикса — это **legacy**: старые данные без истории.

---

### Сценарий 4 — Я хочу разобраться, что такое «TM-запись»

1. Посмотри на колонку **Kind**: что именно переводится — лемма, n-грамма, кластер, поверхностная форма?
2. Посмотри на **Status**: перевод черновой, одобрен или отклонён?
3. Посмотри на **Origin**: кто создал запись — пользователь, импорт, MT?
4. Посмотри на **Src**: источник ещё активен или был удалён?

---

### Сценарий 5 — Я хочу отметить несколько записей как шумовые

1. Выбери нужные строки (Ctrl+Click или Shift+Click).
2. Нажми правую кнопку мыши на выделенном.
3. Выбери **Mark selected as Noise**.
4. В ячейке Noise появится `Noise (manual)` — это значит, что вы лично пометили их как шум.
5. `(manual)` — гарантия того, что эта пометка сделана человеком, а не программой.

## 12. Краткий словарь терминов программы

| Термин | Краткое определение |
|--------|-------------------|
| **Лемма** | Основная (словарная) форма слова |
| **Терм** | Тематически значимое слово или словосочетание |
| **N-грамма** | Последовательность N слов подряд в тексте |
| **Биграмма** | N-грамма из 2 слов |
| **Триграмма** | N-грамма из 3 слов |
| **NP-чанк** | Именная группа, выделенная грамматическим анализатором |
| **Кластер** | Группа похожих выражений, объединённых в один терм |
| **TM-запись** | Строка в базе переводов (Translation Memory) |
| **Noise** | Метка «шумовая запись» — малополезная для данной темы |
| **Valid** | Метка «полезная запись» — несёт тематическую ценность |
| **auto** | Решение принято автоматически программой |
| **manual** | Решение принято пользователем вручную |
| **legacy** | Старые данные, для которых история решений не сохранена |
| **draft** | Черновой перевод — не проверен |
| **approved** | Перевод проверен и одобрен |
| **rejected** | Перевод отклонён как неверный |
| **PMI** | Метрика: насколько слова «притягиваются» друг к другу |
| **Keyness** | Метрика: насколько единица характерна для данной темы |
| **Termhood** | Метрика: общая оценка «терминологичности» единицы |

| **Found:** | Количество строк при текущем фильтре |

## Приложение: трёхуровневое понимание системы

### Уровень 1 — Для первого входа

- Есть слова (леммы) и есть словосочетания (термы).
- Программа нашла их сама. Вы их проверяете.
- Noise = малополезное. Valid = полезное.
- Фильтр — это не удаление, а просмотр.

### Уровень 2 — Рабочее понимание (после 1–2 часов в программе)

- Dictionary = леммы. Terms = кластеры. TM = переводы.
- Kind показывает, как терм был найден.
- Суффикс (auto)/(manual) — кто принял решение.
- Статус перевода и статус noise — это разные, независимые оси.

### Уровень 3 — Углублённое понимание (для продвинутых пользователей)

- Режимы извлечения (Overwrite / Replace Layer / Merge) влияют на то, какие записи создаются.
- Провенанс (происхождение) записи хранится в нескольких полях: Origin, Source Ref, Src, noise_source.
- TM-записи могут быть привязаны к глобальному слою (tm_global) — это механизм распространения лучшего перевода на все проекты.
- Фильтры работают на стороне отображения и не влияют на базу данных.
- Метрики (PMI, Keyness и другие) вычисляются при извлечении и не меняются при ручных правках.
