# Epic 5C: Candidate Persistence — User Guide

> **Версия:** Epic 5C (2026-03-22)
> **Область:** Terms view — параметр Min freq

---

## Что изменилось и почему это важно

До Epic 5C параметр **Min freq** был параметром извлечения: кандидаты ниже порога
отбрасывались при записи в базу и пропадали навсегда. Изменить порог означало
запустить полное переизвлечение.

**После Epic 5C Min freq — это фильтр отображения.** Все кандидаты сохраняются
при извлечении; Min freq управляет тем, что вы видите в таблице прямо сейчас.

---

## Как пользоваться

### Первое извлечение

1. В Terms view выберите режим **Full Overwrite** (по умолчанию)
2. Установите Min freq = 1 (или любое значение — это теперь не влияет на
   полноту сохранённых данных)
3. Нажмите **Extract Terms**

После завершения: в базе хранятся **все** кандидаты независимо от частоты.

### Исследование порога

После одного извлечения можно менять Min freq в реальном времени:

```
Min freq = 1  →  таблица показывает ВСЕ кластеры (включая редкие)
Min freq = 2  →  таблица обновляется мгновенно — без переизвлечения
Min freq = 5  →  снова мгновенно
Min freq = 10 →  снова мгновенно
```

Выбирайте порог, наблюдая за количеством кластеров в таблице, до тех пор пока
список не станет рабочим.

### Продолжение прерванного извлечения (Resume)

Если извлечение было прервано (краш, ручное закрытие), следующий запуск
предложит продолжить с того же места.

**Важно:** смена Min freq между сессиями **не мешает resume**. Приложение
распознаёт прерванный run по структурным параметрам (какие n-граммы, NP или нет),
а не по порогу частоты.

```
Сессия 1: Extract, Min freq=1, обработано 60% → закрыто
Сессия 2: Min freq=3 (изменили), Extract → resume с 60% ✓
```

### Работа с режимами извлечения (Epic 5B)

Min freq работает одинаково во всех трёх режимах:

| Режим | Что сохраняется при Extract | Min freq при просмотре |
|---|---|---|
| Full Overwrite | Всё (freq ≥ 1) | Фильтр отображения |
| Merge | Добавляет новое (freq ≥ 1) | Фильтр отображения |
| Replace Layer | Заменяет слой (freq ≥ 1) | Фильтр отображения |

## Типичные сценарии

### Сценарий A: Новый корпус, неизвестный оптимальный порог

```
1. Extract → Full Overwrite → ждёте завершения
2. Min freq = 1 → смотрите общий объём кандидатов
3. Min freq = 3 → убираете hapax legomena
4. Min freq = 5 → остаётся рабочий список
5. Работаете с кластерами при Min freq = 5
   (редкие кандидаты по-прежнему в базе — можно вернуться к Min freq = 1)
```

### Сценарий B: Добавлены новые документы

```
1. Merge → добавляет новые кандидаты из новых документов
2. Min freq = 2 → список автоматически включает новые кластеры
3. Не нужно трогать уже кюрированные кластеры
```

### Сценарий C: Хочу обновить только биграммы

```
1. Replace Layer (n=2) → удаляет только биграммы, переизвлекает их
2. Триграммы и NP-кластеры остаются нетронутыми
3. Min freq меняется в реальном времени как обычно
```

## Известные ограничения

**Счётчик скрытых кластеров отсутствует.** Таблица показывает видимые
кластеры, но не сообщает, сколько скрыто текущим Min freq. Это планируется
в следующей итерации (Epic 5D).

**Предупреждение о росте данных отсутствует.** При Min freq = 1 на больших
корпусах (>1000 документов) база может вырасти значительно. Приложение пока
не предупреждает об этом. Рекомендуется использовать Min freq = 1–2 для
исследования, а для production-кюрации — порог ≥ 3.

**Эффект только на новые извлечения.** Если проект был извлечён до Epic 5C
(с предыдущим порогом), изменение Min freq покажет только кандидатов выше
старого порога — данных о редких кандидатах в базе нет. Для заполнения
полного пула нужно повторить Extract (Full Overwrite с Min freq = 1).

## Техническая справка (для advanced users)

### Где живёт фильтрация

```
Extraction: _store_ngrams / _store_np_chunks / accumulator → БЕЗ фильтрации
Display:    list_term_clusters → WHERE freq_abs >= min_freq
```

### params_hash после Epic 5C

Хэш run'а больше не включает `min_freq`. Два запуска с одинаковыми
`ngram_ns`, `np_max_len`, `enable_ngrams`, `include_np`, но разным `min_freq`
считаются одним и тем же run'ом и могут resume друг друга.

### algo_version

`_TERM_EXTRACT_ALGO_VERSION = 2`. Запуски, созданные до Epic 5C (v1),
не будут resume-иться — они хранят неполный пул кандидатов.
Первое извлечение после обновления начнёт новый run с v2-семантикой.
